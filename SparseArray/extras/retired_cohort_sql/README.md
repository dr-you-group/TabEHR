# Retired cohort definitions

The cohort SQL of the task set this study used until 2026-11-05. Kept, not
deleted: the definitions are still valid ATLAS exports, and bringing one back is
two steps rather than a rewrite.

Moved here out of `inst/sql/sql_server/`, which is the folder
`SparseArray::createCohorts()` reads, so nothing here is built or installed any
more. `inst/settings/CohortsToCreate.csv` lost the matching rows at the same
time.

| Files | Cohort ids | Used by the tasks |
|---|---|---|
| `*_phenotype.sql` (27) | 2001–2027 | `phenotype2001`…`phenotype2027`, the CCSR diagnosis groups recorded during the index stay |
| `Death.sql` | 1001 | `death7`, `death30` |
| `Long_length_of_stay.sql` | 1002 | `longStay` |
| `Heart_failure.sql`, `Afib.sql`, `Coronary_heart_disease.sql`, `Essential_hypertension.sql`, `Hypothyroidism.sql`, `T2DM.sql`, `GI_bleeding.sql` | 3001–3007 | the previous `newDx` set, seven diseases |

The 27 phenotype files were generated by `extras/MakeIcd10CcsrCsv.R` →
`extras/AddSnomedToIcd10CcsrCsv.R` → `extras/MakeOutcomeCohortSql.R` from
`codes/icd10ccsr.csv`. Those three scripts and that CSV are untouched, so the
set can be regenerated rather than restored.

## Bringing one back

1. Copy the `.sql` file back into `inst/sql/sql_server/`.
2. Add its row to `inst/settings/CohortsToCreate.csv` (`atlasId,atlasName,cohortId,name,type`).
3. Add the task to `extras/MakeStudySettingsJson.R` in the TabEHR repository and
   regenerate `inst/settings/studySettings.json`.

The cohort ids above are not reused by the current outcome set, which starts at
3101, so a restored definition cannot collide with it.

## What replaced them

`codes/newdx_icd10.csv` → `extras/AddSnomedToNewDxCsv.R` →
`extras/MakeNewDxCohortSql.R`, building 21 outcomes (cohort ids 3101–3121) from
the ICD-10 code list of the reference table, mapped to SNOMED and expanded over
`CONCEPT_ANCESTOR` descendants. The only task kept from the previous set is
`readmit`, which uses cohorts 1000 and 1003 and needs nothing from this folder.
