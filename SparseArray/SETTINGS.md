# SparseArray settings

`extras/CodeToRun.R` reads site-specific values from environment variables.
Keep database credentials outside tracked files.

## Environment

Set these variables before running the study:

- `SPARSE_ARRAY_ANDROMEDA_TEMP_FOLDER`: local Andromeda temporary folder.
- `SPARSE_ARRAY_OUTPUT_FOLDER`: study artifact folder.
- `SPARSE_ARRAY_COVARIATE_SETTINGS_FILE`: covariate settings JSON file. Leave
  empty to use the settings installed with the package.
- `SPARSE_ARRAY_JDBC_FOLDER`: JDBC driver folder. Leave empty to use the driver
  installed in the image.
- `SPARSE_ARRAY_DB_SERVER`, `SPARSE_ARRAY_DB_PORT`: SQL Server location.
- `SPARSE_ARRAY_DB_USER`, `SPARSE_ARRAY_DB_PASSWORD`: SQL credentials.
- `SPARSE_ARRAY_CDM_DATABASE_SCHEMA`, `SPARSE_ARRAY_COHORT_DATABASE_SCHEMA`,
  `SPARSE_ARRAY_COHORT_TABLE`: OMOP CDM and study cohort locations.
- `SPARSE_ARRAY_BATCH_SIZE` defaults to `1000000`.

## Covariates

The packaged settings live in `inst/settings/covariateSettings.json` and are
regenerated by `extras/CreateCovariateSettings.R`:

```r
covariateSettingsArgs <- list(
  useConditionOccurrence = TRUE,
  useDrugExposure = TRUE,
  useProcedureOccurrence = TRUE,
  useMeasurement = TRUE,
  timePart = "day",
  timeInterval = 30,
  sequenceStartDay = -359,
  sequenceEndDay = -1
)
saveCovariateSettings(
  covariateSettingsArgs = covariateSettingsArgs,
  file = covariateSettingsFile,
  settingsType = "temporalSequence"
)
```

These are temporal sequence settings, the main path of this package. FeatureExtraction
computes the position of every covariate on the server as

```text
timeId = FLOOR(DATEDIFF(timePart, eventDate, indexDate) / timeInterval)
```

so `timePart` (`"day"`, `"month"`, or `"year"`), `timeInterval`,
`sequenceStartDay`, and `sequenceEndDay` are all required: together they define
the time axis of the sparse array, one index per interval, ordered by `timeId`.
The settings above are thirty-day intervals covering the year before the index
date, giving the twelve positions `timeId` 0 to 11 — so time index 1 is the
interval nearest the index date, not the oldest one. Reverse the time dimension
downstream if a model needs oldest-to-newest input.

Keep `timePart = "day"` when a reproducible time axis matters. Day arithmetic is
exact, so the axis follows from the settings alone. With `"month"` or `"year"`
the server counts calendar boundaries, so the axis spans the observed positions
instead and the `startDay`/`endDay` columns of `timeMap` are empty.

Temporal window settings stay supported for comparison runs: pass
`temporalStartDays` and `temporalEndDays` of equal length with
`settingsType = "temporal"`, where each pair is one position on the time axis.

Non-temporal analyses such as `useDemographicsGender` return covariates without
a `timeId` and cannot be placed on the time axis. Leave them out of the
settings, or pass `dropStaticCovariates = TRUE` to `execute()` to exclude them
from the array and list them under `staticCovariateRef` in the result.

Install the package and run `Rscript extras/CodeToRun.R`. The runner calls
cohort creation, feature extraction, long-format export, and sparse-array
creation explicitly.
